> 覆盖什么、何时读：浏览器半边的实现细节——手机端断点、胶囊与 hero 行的对齐做法、草稿迁移的时序与回滚、设置页的列宽与触摸尺寸、右侧边栏变更记录页的注册、平铺列表与左右对比、以及「首条消息才创建」为什么做不到。改 `src/client/` 的任何界面或座位代码时读。

## 界面实现细节

- **手机端（≤ 600px）不做同一行悬浮对齐**：与宿主手机断点对齐，`conversation.input.dock` 恢复正常文档流，控件放在选择目录 / Agent 下一行、输入卡片上方，左侧 padding 为 20px。必须同时覆盖 `data-phase='hero'` 与嵌入式的 `data-content-phase='hero'`，将 row 的 `height` / `margin` 与 pill 的 `position` / `right` / `bottom` 全部重置。分支菜单 wrapper 允许收缩，长分支省略而 worktree 段不收缩；桌面布局保持下面的对齐方式。

- **胶囊与 `选择工作区 / 模式` 同一行是靠 CSS 对齐的**：hero 那一行的两个槽（`conversation.hero.workspace`、`conversation.hero.agentPreset`）都是 single 槽，第三方插件没有可注册的座位。控件实际注册在 `conversation.input.dock`（order -10，排在最前），在 `data-phase='hero'` 时把这一行压成 0 高度、抵消 `.composerHero` 的 8px 行距，再用 `bottom: calc(100% + 4px)` 悬在输入卡片上方 4px 处、`right: 28px` 收在卡片右边缘内 12px——下边距取 4px，右边距取 12px 是因为卡片右上角是 22px 圆角，靠太近会像压在弧线上；12px 也正好是左侧 workspace 胶囊图标距卡片左边缘的距离。胶囊自身 24px 高、13px 字，和旁边 28px 的 ghost 胶囊同一种语言（无边框、无底色，靠 hover 填充和两段之间 12px 高的细分隔线成形），整体矮一档；`worktree` 一段是 `☐ <新建工作区图标> worktree`：图标跟在勾选框之后、紧贴文字，用的是 `IconProjectAddOutlineRegular`——侧边栏「添加工作区」那个图标，因为这个 check 的结果正是"这个 checkout 变成一个新工作区"；勾选框、图标、文字同在一个 label 里，点哪里都是勾选。两段的字都是 13px/500，和左侧 ghost 胶囊一致。两者顶边对齐。因此：非 hero 阶段它仍退回自己的一行（此时本来也不渲染），hero 行距若被上游改动，对齐会差一点；若别的插件往这个 dock 里注册了 order < -10 的条目，控件会贴到那条的上面。
- **草稿必须跟着人走**：勾选后切到的是**另一个会话**，输入框属于页面而不属于会话，所以未发送的草稿（文字、引用、附件）要在导航之前搬到新会话那边，且**绝不发送**。顺序被 `openWithDraft`（`src/client/draft-transfer.ts`）固定为 **暂存 → 导航 → 清空原会话**，并且**从头到尾同时持有源会话与新会话两条 retain**：`sessions.retain` 是 `mainView` 引用之外唯一能阻止旧会话的输入 shell（连同它的附件）在导航换主引用时被销毁的东西。任一步失败都整体回滚（新会话清空、附件重新绑回源会话），错误经座位的 `error` 显示，**原草稿一字不丢**——包括导航已被拒绝、而后用户再点一次重试的情况。三个前置拒绝：源会话正在提交（`adjudicating` / `submitting`）、目标会话已有草稿、用户 git 还在跑时又切了会话（`shown !== sourceId`，此时连导航都不做，绝不把别人的草稿搬走）。跨会话搬草稿用的是宿主自己的做法（`ui-conversation` 的 `selectWorkspace`）：把语义快照交给 `setDraft`，由它连同引用芯片一起还原——公开签名把该参数收窄成 `string`，所以 `DraftInputFace` 显式写宽，不自行按偏移重插芯片。**语义快照是能力探测后才提交的**（`stageSnapshot`）：0.2.0-rc.x 宿主的 `setDraft` 只收纯文本，对象参数会在编辑器的 `text.replace` 处抛 `TypeError`——那是任何非空草稿都失败的原因（与图片无关）。探测用空语义快照：受支持的版本上是空操作（空文本早退），不支持的版本在碰状态前就抛错；回退时按宿主自己的搬法只传纯文本，引用芯片降级成它的剪贴板文字，附件照搬。芯片还原失败不是能力答案，仍走整体回滚。
- **设置页是设置列，不是一级页面**：`SettingsSection.module.css` 的 `.page` 就地声明 `container: worktree-settings / inline-size` 并 `max-width: 760px`（与宿主 `ui-settings-plugin-inventory` 的 `.section` 同形），**不套** `calc(960px + …)`——设置弹窗内容区实际只有约 560px。标题、卡片、提示都是这一个 flex 列的子元素，共用同宽同左边界；行距仍由各行自己的 margin 表达，不加 `gap`。**按主题分三张卡**（`.card`，导航名「文件备份」）：上卡「Git 账号」放账号连接管理（`SettingsGitAccountsCard`），中卡「Worktree 设置」放创建子仓库、扫描层级、存储位置，下卡「自动备份」放会话文件保护、拦截删除命令、显示变更记录侧边栏。Git 账号卡不是把主面板整页塞进设置列：它只复用 `AddAccountDialog` / `RemoveAccountDialog`，紧凑列出账号（每个账号一张小卡片，未验证 SSH 账号带 warning Tag）并提供**添加账号 / 扫描已有授权 / 移除**，扫描完成只弹一条点名新增账号的 Toast、不铺结果卡片；有账号时再给一个「在『Git 账号』页查看项目」的跳转——点击先 `close()` 关掉设置弹窗、再 `layout.selectPanel('git-accounts')` 切主面板（顺序反了页面会停在弹窗后面）。卡片取设置卡材料（`--dsw-radius-xl` + `0.5px --dsw-alias-settings-card-stroke` + `--dsw-alias-settings-card-fill`，**不加** elevation 阴影），卡内最后一行不画分隔线；Git 账号卡的按钮行自己 `flex-wrap`（设置内容列只有约 560px，窄到 317px 时两枚按钮必须换行，不能撑出横向滚动）。窄容器（`@container (max-width: 520px)`）下每行换行、卡片 padding 收到 12px，控件落到说明下一行。触摸设备（`@media (pointer: coarse)`）把行抬到 44px：Switch 本体固定 36×20 不动，只用按钮上的透明 `::after` 扩大命中区；文本输入 16px/44px、分段选择每段 44px。**依赖行文案要跟着依赖走**：`denyDestructiveCommands` 与 `backupSidebar` 都只在 `fileGuard` 开时有意义，所以守卫关掉时两者置灰并换成 inactive 文案，而不是留一个没有解释的灰色控件。
- **变更记录页是右侧边栏标签页，不是主面板**：`src/client/index.ts` 用公开的两段式路径注册——类型进 `ctx.sidebarRightTabs`（`id` = 包名 + `/backup`，`kind` = `worktree-backup`，附一个「开始」页入口），主体进 keyed 的 `sidebar.right.pane.tab`（key 必须是同一个 `id`）。**不注册 title 座位**：标签文字在打开时就被记录进布局，页面是单例（`multiple` 不设）。主体内不能订阅外部源、也拿不到 `ctx`，数据全靠注册时注入的 `list` / `restore` / `compare`（同一个对象反复返回，否则每次渲染都会重新发请求）。页面本身的骨架、空态、失败态与局部 busy 按宿主界面规范写：列表在刷新期间保留上一次成功内容，只有刷新按钮变灰；空态说明"为什么会空、什么会填满它"。页面覆盖**当前会话及其子会话**，所以 `list` 的条目带 `sessionId` / `depth` / `sessionLabel`：行身份 = 「`sessionId` + `relative`」，还原与对比都发条目自己的 `sessionId`。
- **备份列表必须平铺**：一行一个文件，不给目录行、不做缩进（`BackupPanel.module.css` 的 `.list` 是普通 `ul`，`.row` 是 flex 行）。长路径**换行而不是省略**（`overflow-wrap: anywhere`），因为路径尾部才是识别文件的部分。不显示“已修改/已删除”状态标签；已删除文件路径用 `<s>` 删除线并提供本地化读屏说明，还原成功后移除删除线。**子会话取走的副本在路径下多一行归属标签**（`subsessionLabel` 的文本：有 label 写「子会话 · <label>」，没有只写「子会话」；`title` 带完整 session id），本会话自己的行不加任何标记；同一路径可能在本会话与子会话各有一行，所以两行的还原/对比 `aria-label` 都要带归属，否则读屏无法区分。按钮用宿主 `Button`（`outline` + `size="sm"`），还原结果三态直接写在按钮文字上（还原 / 还原中… / 已还原）并把失败原因写在行内——不许只把按钮变灰。每行按钮的 `aria-label` 带文件名，否则一列"还原"无法用读屏区分。
- **对比详情是同标签页内的主从切换**：点路径把列表换成左右两栏（`BackupDetail.tsx` + `diff-columns.ts`），顶部是返回按钮、文件名、还原按钮；子会话的副本在文件名后再挂同一个归属标签（窄栏里 `max-width: 40%` 省略，`title` 给完整 id），还原按钮的 `aria-label` 同样带归属。不新开弹窗、不另注册标签类型。两栏各自 `overflow: auto`，**横向滚动独立**（两侧行长度不同），纵向靠 `scrollTop` 互相同步；行高固定 `1lh`、行数由 `toColumns` 保证两侧相等，所以对齐靠结构而不是测量。行号列 `position: sticky; left: 0` 且 `background: inherit`，横向滚动时行号不跑掉；行底色用 `--dsw-alias-code-diff-added/deleted`，空位用 `bg-layer-1`、gap 用 `bg-layer-2`；打开时定位到第一处改动。窄栏就靠横向滚动条读，**不做响应式简化版或统一视图**。二进制的「忽略空白 / 高亮单词 / 逐块撤销」不做。
- **"开关只在首条消息时才创建"做不到**：客户端 composer 的提交是 ui-conversation 内部的输入状态机，槽位里没有"提交前"钩子（`conversation.composer` 是 chain，选中者只能自己重写整个 composer；`conversation.composer.bar` 是 single，注册进去会把输入框顶掉），Host 侧也只有 `session/prompt` 这个 RPC；而 `SessionHeader.cwd` 又是创建时冻结的不可变字段。所以"先开关、首条消息再建"需要给 harness 加一个提交前扩展点，插件自身无法实现。当前行为是**点击即创建并切过去**。
- **Git 账号页是一级主面板，不是设置列、也不是右侧栏标签页**：`src/client/index.ts` 同时注册 `main`（keyed，key = `git-accounts`）与 `sidebar.panellist`（`id` 必须同为 `git-accounts`，order 20）；页面组件 `GitAccountsPage` 的 props 是 `PropsRuntime<'main'> & InjectFace<GitAccountsInjected> & PropsLocale<'worktree'>`，数据全走 `src/client/git-accounts-api.ts` 构造的那一份注入面（`snapshot` / `addAccount` / `removeAccount` / `scan` / `projects` / `saveIdentity`），**组件内不 fetch、不 import 路由、任何 DOM 都不出现 token**（令牌只在「添加账号」对话框的局部 state 里，关闭即清空）。页面几何套一级页面规则：`.content` 用 `max-width: calc(960px + 2 * clamp(24px, 4vw, 48px))` + 同款 padding + `container: git-accounts-page / inline-size`；三张卡（`--dsw-radius-xl` + `0.5px --dsw-alias-border-l1` + `--dsw-alias-bg-layer-1`）分别为 Git 身份、账号、项目。**窄容器（≤640px）的列向重排有个坑**：`.form` 改成 `flex-direction: column` 后，字段的两栏基准 `flex: 1 1 240px` 会变成 240px 的**高度**，把身份卡撑到 600px 以上——列向时字段必须 `flex: none` 让内容定高（已修，别把这条规则删掉）。刷新/翻页/扫描期间保留上一次成功内容、只显示局部 busy；失败保留数据 + 行内原因 + 重试；空态说明"为什么空、下一步做什么"；身份保存、移除、复制、扫描都有进行中/成功/失败三态。**验收必须用真实浏览器**：在隔离实例上走通"侧栏入口 → 页面 → 加账号（令牌被拒与成功）→ 扫描 → 选账号看项目 → 加载更多 → 复制地址（读剪贴板）→ 保存身份 → 移除确认 → 390px 窄容器"，并截图核对浅色/深色两套主题；jsdom 单测与构建都不能替代这一步。
